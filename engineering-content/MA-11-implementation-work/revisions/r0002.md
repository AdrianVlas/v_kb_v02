# MA-11 Candidate Revision r0002

## Status

CANDIDATE — CONTROLLED CONTENT REFINEMENT

## Purpose

Define the candidate container for implementation work without implying that implementation has been performed, verified, or accepted.

## Candidate scope

MA-11 may record:

- implementation tasks derived from MA-10;
- work-item identity and lifecycle;
- implementation references and change scope;
- clarification requests and unresolved blockers;
- links to later implementation evidence when such evidence exists.

## Work-state rules

- planned work is distinct from completed work;
- implementation content must retain its input basis;
- no source code, build result, test result, or acceptance is inferred from a work item;
- unresolved authority or scope is recorded as a blocker;
- quality status remains provisional while Q-BC07 is open.

## Authority boundary

MA-11 does not establish implementation ownership, completion, verification, or acceptance authority. All work remains candidate until separately evidenced.

## Open questions

- Q-BC07 — boundary and quality-status dependency;
- Q-AUTHORITY-001 — authority assignment;
- Q-SOURCE-REVISION-001 — source revision basis.

## Exclusions

Production source code, completed implementation claims, verification evidence, acceptance records, and unsupported quality status are excluded.
